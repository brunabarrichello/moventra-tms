## Objetivo

Introduzir um subsistema transversal de **Dead Letter / Quarentena** para falhas terminais de mensageria e Jobs, com persistência durável, isolamento tenant, governança, auditoria e reprocessamento idempotente.

DLQ no Moventra não é apenas uma queue física do RabbitMQ. O broker pode transportar mensagens dead-letter, porém a fonte operacional auditável deve ser provider-neutral e durável.

## Princípios

```text
provider-neutral na aplicação
+
RabbitMQ DLX/DLQ como adapter de transporte
+
PostgreSQL como registro operacional durável
+
reprocessamento idempotente
+
RBAC + RLS + Audit no backend
+
sem edição arbitrária de payload
+
sem loop infinito de redelivery
```

## Gate de conclusão

A fase somente poderá ser marcada `EVIDENCED / CONCLUDED` após evidência objetiva de:

- migration/validation SQL em ambiente controlado;
- RLS e least privilege;
- state machine e concorrência segura;
- idempotência de reprocessamento;
- RabbitMQ DLX/DLQ real;
- APIs administrativas protegidas por RBAC e tenant scope;
- auditoria e observabilidade sem dados sensíveis;
- CI completo;
- Staging;
- rollback/restore;
- aprovação humana explícita para Production;
- smoke e documentação final.

Até lá, a fase 027 permanece bloqueada.
